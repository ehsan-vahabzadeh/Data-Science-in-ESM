# Research: chronological training for forecast correction

Research checked 11 November 2026. These sources inform an evaluation design; they do not establish that a particular window or model will work best on our data.

## Split and model updates

- The [TensorFlow time-series tutorial](https://www.tensorflow.org/tutorials/structured_data/time_series) keeps train, validation and test periods in chronological order and computes normalisation statistics from training data. Its sliding input windows construct sequences for a neural-network example; they do **not** require retraining a regression model after each date. For our tabular forecast-error regression, each matched forecast and reference is a row, with an explicit forecast lead and timestamps.
- A **fixed model** is fitted once on an earlier period and applied unchanged to later cases. An **expanding training window** refits on all eligible past examples as the forecast date advances; a **rolling window** refits using only a bounded recent interval. These describe training policies, distinct from the input windows in the TensorFlow example. Scikit-learn's [TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html) uses successive expanding training sets and supports a gap and maximum training size. Its splits operate on ordered samples: our multiple locations and leads per day require date-grouped boundaries, and a row-count gap alone does not model data availability.
- ECMWF's [calibration memorandum](https://www.ecmwf.int/sites/default/files/elibrary/2014/9607-calibration-medium-range-weather-forecasts.pdf) describes using historical forecast–verification pairs and rolling training periods. Longer windows can reduce estimation variance but may mix changing seasonal relationships. Its 20–40-day examples concern particular ensemble calibration settings, not a recommended universal window for our pooled deterministic regression.

## Availability and leakage

At each simulated prediction or refit time, use only forecast inputs actually available then, and only training targets whose reference data had arrived by that time. A valid time before a prediction is insufficient evidence that its ERA5 target was available. Keep all locations and leads for a given valid day together at split boundaries, fit transformations only on the eligible training rows, and choose features and update policy on validation rather than the final test. These are project-specific consequences of chronological evaluation, not guarantees supplied by a standard splitter.

[ECMWF's ERA5 documentation](https://confluence.ecmwf.int/pages/viewpage.action?pageId=185081924) says preliminary ERA5T daily updates reach the Climate Data Store about five days behind real time, with variable availability; final ERA5 replaces preliminary data later and can differ. An operational simulation must specify a conservative availability rule and the version actually available at each refit, or label the experiment retrospective. Likewise, confirm actual forecast delivery time and source: initialization time alone is not availability. A fixed model trained once before a test period avoids ongoing target updates, but still needs all its training labels to be available before its first prediction.

## Practical comparison for this project

Use the planned chronological train and validation periods to compare a fixed linear model against a predeclared expanding or rolling refit schedule if the required historical availability can be represented. Use the same forecast cases, target and metrics as the raw forecast and bias baselines. Select policy and features using validation, then freeze the protocol before the 2026 test; if the selected policy refits during test, allow only data that would have been available at each refit and do not use test outcomes to change the protocol. The test is then an assessment of the **updating procedure**, not a single frozen set of coefficients. The existing final ERA5 files alone do not reconstruct historical ERA5T vintages or precise release times.
