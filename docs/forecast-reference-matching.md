# Matching IFS forecasts with ERA5 for error correction

**Research checked:** 6 November 2026. This historical note describes the retired Open-Meteo pilot and matching considerations; TIGGE has different variables and time intervals.

## What the comparison measures

A forecast and reanalysis at different grid centres can still be paired, provided the estimand is explicit: the error of the selected IFS product against the selected ERA5 reference at each requested site. It includes spatial representativeness and processing differences as well as forecast error. A grid value represents an area, not an exact site observation; a common grid does not recover unresolved local weather. Coastal land/sea differences and terrain make this especially relevant for UK farms. ERA5 uses observations and an ECMWF model, so it is not fully independent of IFS, nor is it farm telemetry. See ECMWF's [grid-point interpretation](https://confluence.ecmwf.int/pages/viewpage.action?navigatingVersions=true&pageId=222474069) and [ERA5 data documentation](https://confluence.ecmwf.int/pages/viewpage.action?navigatingVersions=true&pageId=242085805).

For the point API pilot, start with a fixed, recorded mapping for each site and technology: request the same coordinates from both sources, explicitly use `cell_selection=land` for onshore and solar and `sea` for offshore, and retain requested and returned coordinates, their separation, returned elevation, units, model, full URL, response and retrieval time. Open-Meteo documents `land` as a land cell with similar elevation, `sea` as preferring sea, and `nearest` as the nearest possible cell; returned coordinates identify the selected grid-cell centre. Its default elevation adjustment uses statistical downscaling; `elevation=nan` disables downscaling. Fix this setting explicitly, compare `nearest` and the default mapping as a sensitivity analysis, and inspect coastal sites manually. The selection is not guaranteed to place the two products at the same centre. [Open-Meteo historical API](https://open-meteo.com/en/docs/historical-weather-api).

A live check on 6 November 2026 for the pilot’s 15 October 2024 run illustrates the sensitivity. At the wind example, the default and `nearest` requests returned the same IFS centre (52.688927, 1.6822431), but ERA5 moved from (52.75, 1.5) to (52.75, 1.75), reducing the centre separation from about 14.03 km to 8.18 km. At the solar example, both centres were unchanged: IFS (53.391914, 0) and ERA5 (53.5, 0). A shorter distance does not prove better representativeness, and the land/sea classification of those cells was not verified. The retired pilot omitted `cell_selection`. The sensitivity check itself was a live observation, not a saved dataset.

A stronger spatial sensitivity experiment needs gridded fields: remap IFS to the ERA5 grid with a documented method, compare against the point pairing on the same dates, and separately examine coastal, offshore and inland sites. Bilinear interpolation gives a value at a common location; area aggregation is more appropriate when the intended target is a coarse-cell average. Neither establishes which product is right, and interpolation can mix land and sea. Record weights, masks and source grids. ECMWF notes that its own MIR regridding does not use a land-sea mask; this is a warning about that tool, not a claim about Open-Meteo's implementation. [ECMWF regridding](https://confluence.ecmwf.int/spaces/FUG/pages/673550691/Section%2B3.5%2BInterpolation%2Band%2Bre-gridding%2BMIR).

The API documents hourly outputs and past-hour solar means but does not establish here the exact native-to-hourly interpolation for each IFS variable, lead and historical run. Do not assume every hourly value is an independent native hourly forecast or that two products use identical processing. Preserve the provider and product versions and check the original data or ask Open-Meteo before interpreting sub-hourly or high-frequency differences.

## Match time and physical quantity

Use UTC throughout and key each pair by site, run initialization, valid time and variable. For a 12 UTC run on day D, instantaneous 100 m wind at 00–23 UTC on D+1 has leads 12–35 hours. Open-Meteo's ordinary shortwave radiation is the **preceding-hour mean** in W/m²: the 24 intervals of D+1 end at 01 UTC on D+1 through 00 UTC on D+2, corresponding to lead hours 13–36. Include that last endpoint. Do not pair an instantaneous radiation field with an hourly mean. [Open-Meteo Single Runs](https://open-meteo.com/en/docs/single-runs-api), [Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api).

If using raw accumulated energy instead, inspect its actual step metadata and units before calculating interval means: difference cumulative values only when that product accumulates from the run start, then divide by interval seconds; do not difference an already interval-accumulated series. ERA5 hourly forecast accumulations cover the preceding step, and its timestamp is the end of that interval. [ECMWF ERA5 time and steps](https://confluence.ecmwf.int/pages/viewpage.action?pageId=85415133). Check UTC boundaries, interval length, missing values, units, and physically plausible radiation and wind before scoring. A run's initialization is not its availability: Open-Meteo says global forecasts typically need 4–6 hours for computation and distribution. Set a decision cutoff and verify actual provider availability against it rather than assuming 12 UTC output was available at 12 UTC. [Single Runs API](https://open-meteo.com/en/docs/single-runs-api).

## Forecast provenance and evaluation

The Single Runs API preserves run identity, unlike a stitched latest-forecast series. Its documentation says IFS data are available from 14 March 2024 and calls early data 49r1 hindcasts, but does not specify the exact boundary, initialization data or production date for every archived run. ECMWF says cycle 49r1 became operational on 12 November 2024, so a 49r1 run before that date cannot be the operational forecast issued then. Do not infer that all later records are as-issued solely from the cycle date; obtain provider confirmation or compare archived raw operational runs, including cycle, initialization and availability. Mark unconfirmed cases as provenance unknown. Hindcasts can support a separately labelled experiment but may not represent information or model versions available at the historical decision time. [Open-Meteo Single Runs](https://open-meteo.com/en/docs/single-runs-api), [ECMWF cycle history](https://www.ecmwf.int/en/forecasts/documentation-and-support/changes-ecmwf-model).

Train on archived forecasts paired with later ERA5, not ERA5 alone: predict `ERA5 − IFS`, then add the prediction to IFS. Begin with raw IFS, a training-period mean-bias correction and a regularized linear correction; compare more complex models only on the same held-out rows. Split chronologically by target day across all sites, reserve a final untouched period and tune using earlier rolling windows. Keep all rows from a run/day together. Use only features available by the decision cutoff, fit preprocessing on training data only, and enforce reference availability before each simulated model update: ERA5T typically arrives about five days later and final ERA5 later still. Save the exact reference version and retrieval date; preliminary values can be revised. [ECMWF ERA5 data documentation](https://confluence.ecmwf.int/plugins/viewsource/viewpagesrc.action?pageId=540945091).

Report paired sample counts, bias, MAE and RMSE for raw and corrected forecasts, and skill relative to raw IFS; show wind and daylight solar separately, with errors by lead, season and onshore/offshore/solar. Use the same rows for every baseline, document daylight and missing-data rules, and quantify uncertainty with blocks of days rather than treating correlated site-hours as independent. Inspect multiple seasons and hold out sites as a separate generalization test if deployment includes unseen farms. Evaluate against independent site or station observations where feasible; an improvement against ERA5 is not proof of improvement against site weather or generation.
